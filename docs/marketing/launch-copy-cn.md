## 一、少数派（长文投稿）

**受众**：效率工具重度用户，吃"方法论 + 真实使用场景"，反感纯功能罗列。
**策略**：产品钩子打头（治任务过载），AI-coded 作为文中的意外惊喜，不要开篇就喊。

### 标题（选一，建议 A）

- **A.** 我做了一个会养宠物的待办应用——治好了我"列完清单就不想动"的毛病
- **B.** 把「该做的事」变成「想做的事」：一个四象限 + 番茄钟 + 会成长宠物的开源待办
- **C.** 我用 AI 写完了一整个效率应用，然后它治好了我的拖延

### 正文

> **开头（痛点共鸣，别写产品）**

我试过不下十个待办应用。真正的问题从来不是"记不住要做什么"——清单我列得比谁都勤——而是**列完之后依然不想动**。

清单是一份"债务通知单"。每打开一次，未完成项就提醒你一次：你还欠着这些。久而久之，打开清单本身成了一件需要意志力的事。

所以我想做的不是又一个更快的收集箱，而是一个**让"把事做完"这件事本身有正反馈**的工具。

> **第一部分：先解决"该做哪件"**

Lumo 的主视图是艾森豪威尔矩阵——重要/紧急两条轴切出四个象限，任务拖进去就完事。

这套方法不新鲜，但大部分工具把它做成了一个"标签"。Lumo 把它做成了**主界面**：你一眼看到的不是 47 条待办，而是"Q1 里有 3 件事现在必须做"。

配套两个小设计：
- **AI 一键分类**：新任务丢进来，LLM 判断它属于哪个象限并给出理由；没配 API key 时回退到启发式规则，不会卡住。
- **Q2 停滞提醒**：那些"重要但不紧急"的事最容易烂在原地。超过 14 天没动的 Q2 任务会逐渐变色提醒你——这是我自己最需要的功能。

> **第二部分：再解决"不想动"**

选中任务进入全屏专注模式，番茄钟开始走。计时器跑在 Web Worker 里，**切标签页、最小化都不会断**（这个坑踩过的人应该懂）。

真正的区别在这里：**你有一只宠物，它随你完成任务而成长。**

猫、狐狸、熊猫、狗、机器人，五选一。完成任务积累经验，宠物会升级、进化——幼犬 → 成犬（戴围巾）→ 智慧犬（戴眼镜）→ 传奇（戴金冠）。它会在角落里飘着，偶尔冒一句话。

听起来很幼稚。但我用了三个月，**它确实有效**——不是因为宠物本身多可爱，而是因为它把"完成任务"从"划掉一条债务"变成了"给什么东西喂了一口饭"。反馈的方向变了。

> **第三部分：其他**

- 习惯打卡、日历周视图（拖任务到某天就是设截止日）
- 统计页 + 可分享的周报卡片（会生成一张带数据的图）
- 完整中英双语，运行时切换
- Web / PWA / Windows 桌面端

> **第四部分：一个意外的部分（AI-coded）**

还有件事：**这个项目的每一行代码都是 AI 写的。**

不是"AI 辅助"，是从架构、实现、测试到 CI，全部由 Claude 生成，我只做需求和验收。仓库里 900+ 个前端测试、契约驱动的 API、完整的 CI 流水线，都是这么来的。

这是一个还在进行的长期实验，也是它开源（Apache-2.0）的原因之一——你可以进去翻 commit 记录，看这套工作流到底能走多远。

> **结尾**

永久免费、开源、不需要信用卡。

- 在线体验：<https://task.lumoryxr.com/?ref=sspai>
- 源码：<https://github.com/lumoryxr/lumo-task-web>

如果你也是"清单列得很勤但执行很差"的那类人，也许可以试试换个反馈方式。

## 二、V2EX（节点：分享创造）

**受众**：开发者。**极度反感营销腔**——要素齐全、语气平实、给技术细节、坦诚缺点。

### 标题

```
[分享创造] Lumo Task - 四象限 + 番茄钟 + 会成长宠物的待办应用，全部代码由 AI 编写，Apache-2.0 开源
```

### 正文

```
做了个待办应用，主要想解决"清单列完还是不想动"的问题。

产品上两个点：
1. 主界面是艾森豪威尔矩阵，不是列表。四象限拖拽，配 LLM 自动分类（无 key 时回退启发式）。
   Q2 象限的任务超过 14 天没动会渐变提醒，防止"重要不紧急"的事烂掉。
2. 有一只随完成任务成长的宠物（五种可选，带进化阶段）。
   听起来无聊，但把"划掉一条"换成"喂养一个东西"之后，我自己的完成率确实上去了。

其他：番茄钟跑在 Web Worker 里（切标签页不断）、习惯打卡、日历周视图、
统计导出分享卡、中英双语、Web/PWA/Windows。

技术栈：
- 前端 React 18 + TypeScript + Zustand + Vite + Tailwind
- 后端 Hono + SQLite
- API 契约用 Zod 定义在共享包里，前后端都从它推导类型，OpenAPI 由契约生成
- 测试：前端 Vitest 900+，后端 node:test（含契约一致性、安全、集成分层），E2E Playwright

需要说明的一点：这个项目 100% 的代码由 Claude 编写，我只写需求和做验收。
不是"AI 辅助补全"，是包括架构决策、测试、CI 在内全部生成。
commit 历史是公开的，有兴趣可以直接翻。

目前的不足：
- 后端跑在免费实例上，冷启动可能要等十几秒
- AI 分类需要自己配 key，默认走启发式
- 移动端是响应式 Web / PWA，没有原生 App

在线：https://task.lumoryxr.com/?ref=v2ex
源码：https://github.com/lumoryxr/lumo-task-web （Apache-2.0，可自部署）

欢迎拍砖，尤其是契约那套设计和 AI 工作流部分。
```

## 通用 FAQ（各渠道回帖备用）

**Q：数据存在哪？安全吗？**
自己的实例存自己的库；仓库 Apache-2.0 开源，可以完全自部署。

**Q：AI 写的代码质量怎么保证？**
契约驱动 + 分层测试 + CI 全绿才能合。前端 900+ 测试，后端有契约一致性/安全/集成三层，加 Playwright E2E。

**Q：和滴答清单/Todoist 有什么区别？**
它们是"更好的清单"，Lumo 是"先决定该做哪件，再帮你真的做完"——矩阵是主界面而非标签，专注和正反馈是内建的。

**Q：免费到什么程度？**
全部功能免费，开源，无信用卡。AI 分类需要自己配 key（不配走启发式回退）。
