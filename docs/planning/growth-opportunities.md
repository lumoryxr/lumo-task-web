## A. 传播/获客杠杆(viral / acquisition)

### A1. 可分享的成就卡片 → 一键发社媒(强化现有 ShareCard)
- **假设:** 已有 Stats PNG 导出 / WrappedCard。把"专注 X 分钟 / 连续打卡 N 天 / 本周清空 Q1"做成**更好看、带产品水印和 demo 链接**的分享卡,并加"分享到 X/小红书/微信"的一键入口。
- **杠杆:** 用户自发晒 = 免费获客;每张卡都带回流链接。**这是 indie 产品最高性价比的病毒环。**
- **工作量:** 中(复用现有导出管线 + 模板美化 + 分享 intent)。
- **风险:** 低(纯前端 + 现有能力)。

### A2. 公开只读分享页(share a matrix / a day)
- **假设:** 生成一个只读链接,展示某个"今日安排"或"四象限快照"(脱敏),别人点开即体验产品界面。
- **杠杆:** 从"截图"升级为"可点的落地页",转化更强;天然 SEO 落地页。
- **工作量:** 中大(需后端只读 token + 公开路由 + 脱敏)。**产品+安全决策,建议 PRD 后再定。**

### A3. Onboarding 结束引导"邀请/分享"
- **假设:** 5 步 onboarding 结尾加一步:分享成就卡 / 复制邀请链接。
- **杠杆:** 在用户"啊哈时刻"顺势触发传播。
- **工作量:** 小-中。

## B. 留存/激活杠杆(retention / activation)

### B1. 每日回访钩子:晨间"今天做哪件事"推送/提醒
- **假设:** 已有"每日首要任务推荐"。把它做成**可选的每日提醒**(本地通知 / 邮件 / PWA push),把"打开 app"变成习惯触发。
- **杠杆:** 直接抬 D1/D7 留存——留存是所有增长的地基。
- **工作量:** 中(PWA push / 通知权限 / 频控)。**涉及通知策略,产品决策。**

### B2. 连续专注/打卡 streak 的可视化 + 轻游戏化深化
- **假设:** 已有宠物/游戏化。强化 streak 可视化(日历热力图、里程碑徽章),给"回来"一个即时正反馈。
- **杠杆:** 习惯养成类留存;也产出可分享素材(接 A1)。
- **工作量:** 中。

### B3. 空数据→有数据的更强引导(把 EmptyState CTA 串成任务)
- **假设:** 现有 EmptyState 有 CTA。把首个 EmptyState 的 CTA 串成一个"创建你的第一个任务→分到象限→开一次专注"的 3 步激活流。
- **杠杆:** 抬"新用户当天达成 Aha"的比例(launch-plan §6 的核心激活指标)。
- **工作量:** 小-中。

## C. 开源/社区杠杆(与 launch-plan §3–4 联动)

### C1. 项目内嵌"AI 开发日志"页(把 ROADMAP/Done log 渲染成可读时间线)
- **假设:** ROADMAP 的 Done log 已经是极好的内容源。做一个 `website/` 或产品内的"AI changelog"页,自动从 ROADMAP/CHANGELOG 渲染。
- **杠杆:** 把"100% AI-coded"的故事变成可访问、可传播的资产;SEO + 社区可信度。
- **工作量:** 小-中(纯展示)。**低风险,推荐早做——它同时喂养营销内容线。**

## D. Bug / 打磨 观察清单(基于 ROADMAP 未完项 + 常见风险面)

> 这些多在工程 loop 的射程内(Phase 1/2),此处仅作**优先级建议**,便于你对齐 loop 方向:

1. **Visual consistency(ROADMAP Phase 1 未完,当前 loop 焦点)** — spacing/type/color token 收敛;跨 Today/Matrix/Stats/Settings 对齐卡片节奏。**建议保持最高优先**(直接影响"精致感"→留存/口碑)。
2. **Mobile/responsive 复核(未完)** — 逐页 Pixel-5 级布局验证 + 每页移动端 Playwright smoke。移动端体验直接影响社媒来的流量转化。
3. **Pagination 泛化(Phase 2 未完)** — `people`(#180)/`habits`/`countdowns` 仍是无界数组;上线后数据增长的稳定性隐患。
4. **Error tracking(Sentry/OTel,未完)** — 已有 request-id 关联基础;上线后**没有异常告警 = 盲飞**。建议在营销放量前接上,否则放量遇到问题看不见。
5. **Versioned migrations(未完)** — 替换 ad-hoc `CREATE IF NOT EXISTS`;放量前的数据安全底座。

> **给放量前的一句话建议:** 在启动营销放量**之前**,优先补齐 **D4(异常告警)** —— 没有可观测性就放流量,出问题会静默流失用户且无从复盘。这是"营销 ROI 的保险丝"。

---

## 建议的决策顺序(供参考)
1. 先确认 **launch-plan 的主叙事 + 上线日**(§8)。
2. 放量前接 **D4 异常告警**(保险丝)。
3. 传播环先做 **A1(分享卡强化)+ C1(AI 开发日志页)** —— 低风险、高杠杆、喂内容线。
4. 留存做 **B3(3 步激活流)**,再看 B1(每日提醒,需通知策略拍板)。
5. A2(公开分享页)/ B1(推送)属较大产品+安全决策,建议各写一页 PRD 再排期。
