## 2. 变现层 / Monetization —— 商用的核心缺口（当前 0）

目前 `plan` 字段恒为 `"free"`、`renewsAt` 为占位，**没有任何支付代码**。要收费至少需要：

- **[todo] 支付服务商接入（Stripe 建议）** · **L**。Checkout/Billing Portal、`customer`/
  `subscription` 对象、**webhook**（`checkout.session.completed`、`customer.subscription.*`、
  `invoice.paid`/`payment_failed`）签名校验 + 幂等处理。契约优先建 `@lumo/contracts` 计费 schema。
- **[todo] 套餐与权益模型（entitlements）** · **M**。定义 Free/Pro 的功能与配额（如 AI 用量、
  项目数、同步），后端在每个受限操作处做**服务端 gate**（不能只靠前端隐藏），`users.plan`/
  到期时间驱动。目前 AI 已有 `ai_cloud_used/month` 计量，可作为第一个配额点。
- **[todo] 升级/降级/取消/宽限期（dunning）** · **M**。失败扣款重试、到期降级、取消挽留。
- **[todo] 发票 / 税务** · **M**。启用 **Stripe Tax**（VAT/GST/销售税），发票与收据邮件
  （复用现有 `sendEmail()`）。
- **[todo] 退款与账单政策** · **S**（政策）+ 法务。见 §5。
- **[todo] 定价页 + 结账入口 + 账号页订阅管理** · **M**。前端把现在的"Pro · Coming soon"
  换成真实结账 + 管理入口。
- **合规红利**：卡数据全程走 Stripe，**PCI 范围最小化**（SAQ-A），自己不碰卡号。

> 变现层是最大工作块，粗估 **3–5 周** 到"可稳定收第一笔"。

## 8. 到"第一个付费用户"的建议关键路径

按"最少必要 + 依赖顺序"：

1. **可靠性打底**（不然收了钱丢数据）：付费托管 + Turso PITR + 自动备份&恢复演练 + Sentry +
   uptime 告警。 → §3/§2 之前。**≈1 周**
2. **法务与话术**：法务过 ToS/隐私 + 加订阅/退款条款；落地页"不追踪"话术对账。 → 与 1 并行。**≈law + S**
3. **变现最小闭环**：Stripe Checkout + webhook（幂等/签名）+ 权益 gate（先 gate 一个点，如 AI 用量）+
   账号页订阅管理 + 发票/税。 → 依赖 1。**≈3–5 周**
4. **支持通道 + 状态页 + runbook**：收费即义务。 → 与 3 并行。**≈S–M**
5. 上线后：分析漏斗、安装包签名、文档纠偏、营销站合并。（P2）

> 粗略总量：**到可稳定收费 ≈ 5–7 周**（单人、串并行结合），其中变现层占大头。可靠性与法务
> 是"先决"，变现是"主体"，支持是"义务"。
